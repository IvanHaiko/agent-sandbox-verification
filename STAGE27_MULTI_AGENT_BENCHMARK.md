# Stage 27 — Multi-Agent Architecture Benchmark

**Architecture recommendation: INCONCLUSIVE.** Both configurations produced useful implementations that passed the same frozen external acceptance suite, unchanged project regressions, real PostgreSQL checks, independent tests and deliberate regression controls. Native Codex successfully coordinated the three roles. No engineering-quality advantage for the custom framework was demonstrated on this task.

The complete operational comparison was interrupted by a **coordinator-authored Stage 27 adapter defect**, which stopped Configuration B after its independent tests passed and before its scheduled Reviewer. B's original failed decision is preserved. A separately recorded closeout completed that Reviewer and the common evaluations. This failure cannot responsibly be attributed to the pre-existing framework or used to declare native orchestration superior. Model-usage counters also have incompatible fields and uncertain aggregation scope. The evidence does not justify KEEP, SIMPLIFY or REPLACE for the entire architecture.

Executed on **9 October 2026**. Neither candidate patch was applied to the original Steam ETL checkout.

The task was selected by the benchmark coordinator after inspecting the committed source: implement a PostgreSQL-aware statement splitter and integrate it into the migration runner. The existing `sql.split(';')` breaks quoted semicolons and function bodies. The task spans a new pure Python module, the existing migration runner and focused project tests, with a concrete persistence concern: statement execution and ledger recording remain atomic per file while earlier files remain committed after a later failure. It is distinct from Stage 25's Twitch replacement and Stage 26's Steam Store refactoring.

Both candidates start at **`0653617666399590c853c39f08e8cf97c9eca45c`**. The target's existing staged, unstaged and nonignored untracked work was fingerprinted and excluded through `git archive` of that exact commit. Independent Git working copies avoid modifying the original repository's worktree metadata. Only `src/migrations.py`, new `src/sql_statements.py` and new `tests/test_migration_sql.py` are candidate files. The [frozen task](docs/stage27-verification/task-contract.md) specifies exact interfaces, supported lexical regions, malformed-input behavior, scope, commit behavior, constraints and dependencies.

The [freeze receipt](docs/stage27-verification/freeze.json) predates both implementations and hashes the task, shared evaluator, rubric, requirements and experiment adapter. A then B was predeclared by alphabetical label, without selecting for expected success. The [shared evaluator](docs/stage27-verification/test_external_acceptance.py) was authored by the coordinator from the contract before either candidate existed. Neither competing Implementer nor Tester authored it or received it. No assertion, task requirement or acceptance criterion was changed after candidate exposure. Evaluation occurred after both configurations stopped.

Both configurations used native Linux Codex CLI **0.160.1**, **`gpt-6.1-sol` / `medium`**, Python **3.14.4**, PostgreSQL **18.6**, and the exact committed requirements. [Installed dependencies](docs/stage27-verification/installed-dependencies.txt) match the pinned requirements, including psycopg 3.3.4, pytest 9.0.3 and Ruff 0.15.12. The desktop Windows CLI was also inspected and reported 0.162.0-alpha.2; it was not mixed into the comparison. The baseline passed all 168 project tests before freeze. PostgreSQL used a new disposable cluster and pathname socket, with no production data or credentials.

Stage 25 and Stage 26 assessments, decisions, integrity evidence, model/runtime receipts and active framework source were inspected. Stage 25's successful retry required interventions. Stage 26 produced useful code but failed independent artifact validation and lost rejected test bytes. The current existing collection-before-cleanup correction was retained. Historical timings and test counts were not used as a competing benchmark result. Framework source hashes remained unchanged throughout Stage 27.

The [capability inventory](docs/stage27-verification/native-capabilities.md), [installed CLI help](docs/stage27-verification/native-exec-help.txt) and [feature flags](docs/stage27-verification/native-features.txt) distinguish installed observations from current [official Subagents documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents). Those properties were evaluated separately.

Configuration A used one native CLI Orchestrator and exactly three native subagents: blind Independent Tester, Implementer and Reviewer. It requested fresh contexts with no inherited history. Its Tester designed and froze both files before implementation began. Separate tester, implementer and acceptance Git copies were provisioned; native reviewer configuration requested read-only operation. The Orchestrator, rather than coordinator Python code, delegated, waited, froze artifacts, applied the patch, requested acceptance and collected review. Its [native events](docs/stage27-verification/A/native-events.jsonl), [input](docs/stage27-verification/A/orchestrator-input.md) and [orchestration record](docs/stage27-verification/A/results/orchestrator.json) are retained.

Configuration B used the unchanged Stage 26 native launcher, scope/snapshot validation, Controller-selected input bundles, test facility, artifact freezing and read-only review mechanism. Its Implementer ran first; its completed workspace was removed before the blind Tester ran. The Tester received requirements, interfaces, unchanged fixtures and SQL, with no source tree, candidate, handoff or implementation reasoning. The Controller structurally validated and froze its design and harness before executing acceptance. No Architect model invocation was needed in B because the coordinator supplied the already frozen task; A's model Orchestrator corresponds to B's deterministic coordination. These are documented execution differences, not artificially equal invocation counts.

**Scope limitation:** both configurations used the existing `RoleTestEnvironment` as a common development-test facility. It provided the same predefined unit/integration/lint commands and contained PostgreSQL access. It did not delegate agents or select implementation/test design in A. Consequently, this experiment compares native role orchestration with custom role orchestration while sharing that test infrastructure; it does not demonstrate that all custom runtime support can be removed. The one-off adapter is retained for reproducibility, with no generic new orchestration platform or framework-source changes.

The first A acceptance attempt was invalid. Its native Orchestrator saved a full Git diff containing handoff metadata that did not exist in the acceptance copy. Patch application failed, but the Orchestrator still requested acceptance on original source: **4 failures, 29 errors, 1 pass**. It preserved that result, selected the exact three authorized candidate-file hunks, applied them and reran acceptance: **34/34 passed**. Candidate bytes matched the implementation copy. This was one recorded setup correction within the original native run, with no role resampling, candidate repair or frozen-test edit. It is not evidence that A detected 33 candidate defects.

B implementation and test design both completed with valid artifacts and passed scope/preflight checks. Its frozen independent acceptance produced **40/40 passes**, then `experiment.py` called the framework's strict artifact cleanup with pytest's ordinary scratch symlinks still present. Cleanup raised **`Linked workspace entry`** and prevented the scheduled review from starting. The existing test facility removes its scratch subtree before strict cleanup; the new coordinator adapter omitted that boundary. [The original functional result](docs/stage27-verification/B/independent.json), [failed assessment](docs/stage27-verification/B/assessment.json) and [exact link evidence](docs/stage27-verification/B/failed-cleanup-links.json) are preserved. The assessment's initial `cleanup_passed` covered its listed model workspaces and did not establish cleanup of the separately created evaluation workspace.

The [recorded correction](docs/stage27-verification/interventions.json) removed verified owned scratch subtrees after archiving results, then invoked the unchanged strict cleanup. It was applied equally to A and B's common evaluations and mutation controls. Frozen `experiment.py`, candidates, task and suites remained unchanged. The retained failed evaluation workspace was removed separately after identity verification. B's already scheduled Reviewer was invoked exactly once as a failure closeout, using only B evidence and the common rubric. No Implementer or Tester was retried, no extra role was added, and B's original Controller decision was not overwritten.

The independent suites provide useful behavioral evidence rather than merely large test counts. Both cover all seven categories, assert statement text and boundaries, verify validation before execution, and use actual PostgreSQL for quoted bodies, ledger replay, rollback and prior-file durability. Neither used private new helper names as acceptance dependencies. Both explicitly leave exact console wording and actual default-path discovery incompletely tested; reviewer source comparison and the unchanged suite provide additional compatibility evidence. No line/branch coverage percentage was measured.

Isolation evidence is deliberately separated by property. A's freeze precedes its Implementer start; immutable final hashes support candidate-blind design. A's recorded parent profile was retrospectively probed: its own role files were readable, while B's existing candidate, the shared suite and original target source were inaccessible. This demonstrates tested cross-configuration exclusion for that profile, not per-role filesystem isolation or effective reviewer write denial. Intra-A peer files remained within the permitted parent root; role-level adherence is intended and partly unverified. There is no observed evidence of unauthorized candidate context reaching its Tester.

Its Tester bundle contained no source tree or implementation material. The Reviewer preflight verified read-only inputs and its final snapshot was unchanged. **INCONCLUSIVE** is an evidence limitation, not an architectural preference. The observed code and independent testing outcomes are equivalent on the bounded criteria; native orchestration demonstrably works, and B demonstrates stricter tested role restrictions. The coordinator interruption, shared custom test infrastructure, review-input asymmetry and incompatible usage evidence prevent a faithful complete-architecture efficiency/reliability decision. B has not demonstrated engineering gains that justify its additional machinery on this task, and A has not demonstrated that every custom mechanism can be removed. This single benchmark supplies concrete patches and observations without manufacturing either conclusion.
