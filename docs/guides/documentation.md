# Documentation maintenance

`docs/README.md` is the generated entry point. Only Markdown under `docs/guides/`
and `docs/templates/` is indexed. Historical evidence is deliberately outside that
set. Do not mass-edit reports, receipts, frozen contracts or fixture copies.

Current files start with a JSON object between standalone `---` lines. This is
valid YAML frontmatter, restricted to JSON syntax so the tool needs no dependency.
Required fields are nonempty `title`, `summary`, `status: "current"`, and a nonempty
`related_files` array of repository-relative paths or globs. Every pattern must
match an existing file. Keep each current file within 180 lines; split by topic.

```text
python scripts/docs.py for agent_system/acceptance.py
python scripts/docs.py for scripts/docs.py README.md --json
python scripts/docs.py build
python scripts/docs.py check
```

Lookup accepts Windows separators, new or deleted relative file names. Its glob
matching is case-sensitive and uses Python fnmatch semantics; `*` can match `/`.
Use explicit paths or scoped patterns. Exit 1 means at least one query is unmapped;
exit 2 means invalid input, metadata or stale index. No match is a request for
judgment, not permission to create unrelated documentation.

`build` also writes `.claude/skills/<name>/` as exact byte copies of each
`.agents/skills/<name>/` directory, removing extra files inside those copies only;
`check` reports any drift. Edit the `.agents/skills/` source, never the copy.
Projects without `.agents/skills/` get no copies.

Update only guides affected by behavior or operational changes. Verify descriptions
against implementation and real check results. Rebuild and check the index after
changing metadata or adding/removing guides. Check mode never rewrites files.
The root README is the project's front page; its results table is generated by
`build` from `docs/stage34-verification/summary.json`, and `check` fails when it
drifts or when a relative link in the README, AGENTS.md, CLAUDE.md or a current
guide is broken. The detailed API lives in `docs/guides/reference.md`.
The architecture image is `docs/architecture.svg`, rendered from
`docs/architecture.mmd` by `python scripts/render_diagram.py` (open the printed
local address in a browser); `check` fails when the image's embedded source hash
no longer matches the `.mmd` file.
